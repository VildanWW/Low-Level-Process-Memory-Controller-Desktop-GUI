# 🐇 Модуль Передвижения: Первые задатки

Как заставить персонажа прыгать с идеальной точностью в тот самый микросекундный момент, когда он касается земли? Самый очевидный путь — написать автоматический контроллер. Но игра не отдаст нам управление просто так. Придется разложить её логику по полочкам.

### 🔍 Шаг 1. Ловим биты (Взгляд изнутри)
Первая задача — понять, как игра определяет, где находится игрок. 

1. С помощью Cheat Engine[^1] был запущен поиск неизвестного значения. Так как точное число флага было скрыто, использовался метод относительного отсеивания(`Increased value`/`Decreased value`).
2. Этот подход позволил быстро отсеять миллионы лишних адресов и найти точный статический адрес, который при изменении позволял манипулировать игроком: `client.dll + 0x1E94C0` (`jumpAddress`).

### 🕵️‍♂️ Шаг 2. Ныряем в Ghidra[^2]: Не так ли устроен код?
Чтобы перехватить управление движением, нужно найти функцию, которая обрабатывает пакеты кнопок. 

Мы закинули `client.dll` в **Ghidra**. Так как декомпилятор по умолчанию использует базовый адрес `0x10000000`, мы прибавили к нему относительное смещение функции движения (`moveAddress = 0x9B880`) и перешли по адресу:

### 🎯 Шаг 3. Сердце банихопа: Блок `else`
Мы написали хук-функцию с соглашением вызовов `__fastcall`. Но почему обычный `if` ломает логику, а с блоком `else` всё работает идеально? Посмотрим на этот участок кода:

```cpp
if (airState == 0) { 
    modifiedValue = originalValue | 2; // НА ЗЕМЛЕ: прыгаем
}
else {
    modifiedValue = originalValue & 0xfffffffd; // В ВОЗДУХЕ: отжимаем пробел
}
```
**В чем магия:** Если мы просто зажмем пробел, игра подпрыгнет один раз, бит «залипнет» в значении в изменённом значении и второго прыжка при приземлении не будет. 
Строчка `originalValue & 0xfffffffd` принудительно «отжимает» прыжок в памяти игры, пока персонаж летит в воздухе. Движок игры думает, что мы кликаем по пробелу со скоростью света!

[^1]: Для динамического анализа адресного пространства процесса использовался инструмент **Cheat Engine**, выступающий в роли отладчика памяти.
[^2]: **Ghidra** — программный фреймворк для реверс-инжиниринга (разработки подсистем обратного проектирования) и статического анализа кода, созданный Агентством национальной безопасности (АНБ) США.
